# Giant Text — App Store Connect submission guide

Everything needed to create the App Store Connect listing, plus the pre-flight
checks that have already been done and the ones only you can finish.

- **Bundle ID:** `com.fennel.Giant-Text`
- **Version / Build:** `1.0` / `1`  (`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`)
- **Ships on:** iPhone, iPad, Mac, Apple TV, Apple Vision Pro
- **Extension:** Giant Text Widget (`com.fennel.Giant-Text.GiantTextWidget`)

> **Before you submit, finish the items in [Still needs you](#still-needs-you).**
> Two of them (privacy policy URL, support URL) are hard blockers — App Store
> Connect will not accept the listing without them.

## 6. Screenshots

Generated by `./Tools/screenshots.sh all` into `AppStore/screenshots/`.
That directory is **gitignored on purpose** — upload the files to App Store
Connect, don't commit them.

| Platform | ASC display size | Captured | Count | Folder |
|---|---|---|---|---|
| iPhone | 6.9" | **1320 × 2868** | 5 | `screenshots/iPhone-6.9/` |
| iPad | 13" | **2064 × 2752** | 5 | `screenshots/iPad-13/` |
| Mac | — | **1440 × 900** | 4 | `screenshots/Mac/` |
| Apple TV | — | **1920 × 1080** | 3 | `screenshots/AppleTV/` |
| Apple Vision Pro | — | **3840 × 2160** | 5 | `screenshots/VisionPro/` |

Each size is an exact App Store Connect accepted resolution, so no resizing or
cropping is needed.

**What each shot shows**

1. `01-hero` — "GIANT TEXT" in the Classic theme
2. `02-sunset` — "ON MY WAY" in Sunset Glow (a real use case)
3. `03-ocean` — "HELLO" in Ocean Breeze with the Ripple animation
4. `04-options` — the options sheet (animation picker)
5. `05-themes` — the theme picker, with live "Aa" swatches in each theme's colors

Apple TV only has the three hero shots: tvOS uses a cut-down options menu with
no theme grid, so shots 4–5 would be weak there. macOS skips `04-options` for
the same reason (the theme grid shot covers it).

Every set is captured in dark appearance so each platform's set is internally
consistent.

**Regenerating:** `./Tools/screenshots.sh iphone|ipad|tv|vision|mac|all`.
It drives DEBUG-only `--ss-*` launch arguments in `ContentView.swift`, so it
must run against a Debug build. Those arguments are compiled out of Release
builds and cannot ship. The macOS path captures **by window ID**, so a
screenshot can only ever contain the app's own window, never your desktop.

## 7. App privacy

The app collects nothing. In the App Privacy questionnaire answer:

> **Do you or your third-party partners collect data from this app?** → **No**

That yields a "Data Not Collected" label. This is accurate and verifiable:

- No analytics or crash-reporting SDKs, and no third-party dependencies at all
- No network code anywhere in the project
- Text is stored locally via SwiftData, plus an App Group
  (`group.com.fennel.Giant-Text`) shared only between the app and its own widget
  on the same device
- No account, no sign-in, no advertising identifier

You still must supply a **privacy policy URL** even though nothing is collected.

## 10. Verified before submission

Checked on this build:

- **Zero warnings and zero errors** in **Release** configuration on all four
  platforms — iOS, macOS, tvOS, visionOS — plus the widget extension
- Unit tests: **7/7 passing** (the scheme's test action had never been wired up;
  it is now, so `xcodebuild test` works in CI)
- tvOS app icon and Top Shelf brand assets exist and satisfy tvOS's
  fully-opaque-layer requirement
- Export compliance key present
- App icon asset catalog has no unassigned/orphan entries

Fixed while getting here, worth knowing about:

- **visionOS had never compiled.** It was declared supported
  (`SUPPORTED_PLATFORMS`, device family `7`) but failed with four errors —
  `inputAccessoryView` and `UIScreen` are unavailable on visionOS, and
  `WidgetCenter` needs visionOS 26. Now builds clean.
- **tvOS shipped with no app icon.** There was no `AppIcon.brandassets` at all,
  which is an App Store blocker for tvOS. Generated from the existing logo.
- Settings (font, animation, kerning, max lines, bold/italic) never wrote back
  to `UserDefaults` from the model — persistence depended on a SwiftUI
  `.onChange` staying alive.

## Still needs you

Ordered by how much they block submission.

**Hard blockers**

1. **Privacy policy URL** — required for every App Store listing, even with no
   data collection. Must be a public, reachable page.
2. **Support URL** — required. A public page with a way to contact you.
3. **Signing** — everything here was verified with `CODE_SIGNING_ALLOWED=NO`.
   You need to archive with your real team and distribution certificate, and
   confirm the App Group `group.com.fennel.Giant-Text` is enabled on the App ID
   for both the app and the widget extension.

**Should decide before you ship**

4. **Home screen name is `GT`, not `Giant Text`.** `CFBundleDisplayName` is set
   to `GT`, so that's what appears under the icon. "Giant Text" fits fine under
   an icon, so if `GT` wasn't deliberate, change
   `INFOPLIST_KEY_CFBundleDisplayName` in the project.
5. **54 localizations show the English word "Ripple".** The `ripple` animation
   had no localization entry in any of the 55 languages, so it rendered as the
   raw lowercase key. Every file now has the key, but only `en` is genuinely
   translated — the rest are English placeholders and need a translator.
   `none`, `bloom`, and `jitter` are properly translated in all 55.
6. **Test on real hardware.** Everything above was verified in simulators and on
   this Mac. In particular the iPhone rotate-while-portrait behavior, the
   two-finger-tap gesture, and the widget deserve a pass on a physical device.
7. **Apple TV and Vision Pro** have never run on real hardware. They build clean
   and behave correctly in the simulator, but if you'd rather not support them
   yet, drop `appletvos`/`xros` from `SUPPORTED_PLATFORMS` and remove `3`/`7`
   from `TARGETED_DEVICE_FAMILY` rather than shipping unverified.

**Optional**

8. Marketing URL, and an App Store promo video, if you want them.
9. `Graphics/` holds unused watch/visionOS source art. watchOS isn't in
   `SUPPORTED_PLATFORMS` and has no target, though there is still `#if
   os(watchOS)` code in the source. Harmless, but it's dead weight.
